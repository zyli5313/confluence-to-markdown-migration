Moving a Confluence space to Markdown: what breaks and how to keep it

Teams leave Confluence for docs-as-code, an internal wiki on Git, Notion or Obsidian, and nearly every migration hits the same wall. Confluence pages look like HTML, but the important parts are Confluence's own XML macros. Run a page through a generic HTML-to-Markdown converter and the code blocks, info panels and task lists vanish without a warning. This guide covers what to map and in what order.

Get the right source: storage format

Don't copy the rendered page. Open the page's storage format (… menu → View storage format, or the REST API body.storage). That XHTML still has the macros as elements such as <ac:structured-macro ac:name="code">, which a converter can map on purpose.

What needs explicit mapping

Confluence elementMarkdown target
Code macro (with language)Fenced code block with the language tag
Info / note / warning panelsBlockquote with a bold label, or GitHub > [!NOTE] alerts
Task lists- [ ] / - [x]
Page links (ri:page)Relative links to the new file paths
Attachments / imagesDownloaded files in an assets/ folder

The dochost Confluence to Markdown converter maps code macros, info panels and task lists before it converts, so they come out as fenced code, blockquotes and checkboxes instead of disappearing. It runs in the browser.

A page-by-page checklist

  1. Export the storage format of the page.
  2. Convert it and save it as section/page-title.md, with a slug that matches the old title.
  3. Search the output for macros the converter didn't recognize (ac: leftovers): Jira issue lists, include-page and excerpt macros.
  4. Rewrite page links to relative paths. Keep a mapping CSV of old page ID → new path for redirects.
  5. Download the attachments and fix the image paths.
  6. Diff it visually against the original before you archive the Confluence page.

Macros you should rebuild, not convert

  • Jira issue macros: replace them with a link to a saved Jira filter.
  • Include page / excerpt include: use your docs tool's own include feature, or duplicate the text on purpose.
  • Page tree / children display: generate it from the folder structure.

If the destination is Notion

Markdown is a good intermediate format even when the final home is Notion. Convert the Confluence page to Markdown, clean it up, then use Markdown to Notion so the paste lands as real Notion blocks instead of one long text block.
